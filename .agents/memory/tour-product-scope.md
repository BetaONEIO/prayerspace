---
name: Tour product scope
description: User requirements for real-data onboarding and safe practice in Prayer Space
---

Prayer Space onboarding must teach through real, authorized app screens. Never create fake users, prayers, communities, messages or activity to populate tutorial screens. Explain empty states instead.

**Why:** The user explicitly required interactive onboarding without dummy data, including for older and less confident mobile users.

**How to apply:** Keep onboarding practice optional and non-publishing. Do not send friend requests or force group/community creation. Preserve the user's actual saved drafts and existing prayer, friendship and community behavior.

The user also wants the tutorial to cover Prayer Journal, prayer requests sent to friends, solo prayer, recording prayers and sharing with friends—not only the community/social screens.

**Why:** The user explicitly asked for the app's broader features and provided the main navigation menu as a reference.

**How to apply:** Include the real feature entry points without automatically starting recording, prayer sessions, contacts permission requests or sending/sharing actions.
