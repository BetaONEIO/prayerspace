Please perform a **complete end-to-end audit of the Friends / Connections system across the entire Prayer Space app**.

This is not simply an audit of the "Add Friend" button.

Friendship should be a genuine relationship that affects:

* Friend requests
* Profiles
* Friends lists
* Search and discovery
* Main Feed
* Status updates
* Prayer activity
* Testimonies
* Notifications
* Messaging
* Privacy
* Blocking
* Prayer Groups
* Prayer Communities
* Realtime updates

The goal is to make sure friendships work reliably from beginning to end and that becoming friends actually changes what users can appropriately see and do throughout Prayer Space.

Do not use any:

* Dummy data
* Mock users
* Placeholder profiles

# 1. Audit the friendship data model

First inspect how friendships are currently stored.

There should be **one reliable source of truth** for the relationship between two users.

A friendship should support states equivalent to:

* No relationship
* Request pending
* Friends
* Declined
* Blocked

Friendship must be **bidirectional**.

If User A and User B are friends:

* A should recognise B as a friend.
* B should recognise A as a friend.

Do not require duplicate friendship records unless that is intentionally how the existing architecture works.

Prevent:

* Duplicate requests
* Duplicate friendships
* Sending a request to yourself
* Sending another request when one is already pending
* Becoming friends without acceptance
* Accepting the same request multiple times
* Race conditions if both users send requests simultaneously
* Inconsistent friendship state between users

Reuse the existing database architecture where possible rather than unnecessarily rebuilding the system.

# 2. Sending a Friend Request

From another user's real profile, I should be able to tap:

**Add Friend**

After sending:

* Create a genuine pending Friend Request.
* Associate it with the correct sender and recipient IDs.
* Change the button to **Request Sent**.
* Prevent repeated requests.
* Persist the state after refreshing.
* Persist the state after closing/reopening the app.
* Notify the recipient.
* Do not expose Friends-only information before acceptance.

If sending fails:

* Show an appropriate error.
* Restore the button correctly.
* Do not leave a fake/pending frontend state.

# 13. Friends and the Main Feed

THIS IS PARTICULARLY IMPORTANT.

Once two users become confirmed Friends, their eligible activity/posts should appear naturally in each other's main Feed.

The Feed should contain appropriate content from:

1. The logged-in user.
2. Confirmed Friends.
3. Prayer Community content the user is authorised to see, if Community content is intentionally part of the same Feed.

For Friends-visible content:

`Post → author_user_id → confirmed friendship → authorised Feed`

If A and B are Friends:

* A should see eligible posts from B.
* B should see eligible posts from A.

If C is not their Friend:

* C must not see Friends-only content.

Do NOT:

1. Download every user's posts.
2. Display them all.
3. Hide unauthorised content only in the frontend.

Backend/database permissions must enforce access.

# 19. Anonymous prayers

Be extremely careful with anonymous prayers.

If a prayer is anonymous:

* Do not expose `author_user_id` through the UI.
* Do not expose the author's profile through Activity.
* Do not identify the author through notifications.
* Do not identify the author through Feed metadata.
* Do not expose the author through API responses available to unauthorised users.
* Do not expose authorship through profile Activity.

Friends must not be able to determine who posted an anonymous prayer simply because they are Friends with the author.

Anonymous means anonymous regardless of friendship.

# 30. Friendship vs Prayer Communities

Friendship and Prayer Community membership are completely separate relationships.

Do NOT automatically make Community members Friends.

* Share a Community with someone without being their Friend.

Community membership must not grant Friends-only Feed access.

Friendship must not grant access to private Community content.
